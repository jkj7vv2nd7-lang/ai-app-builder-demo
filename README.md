# ローカルAIアプリ開発エージェント v3

アイデアを入力すると、ローカルのOllamaモデルが「要件定義 → デザイン設計 → 実装 → QA」の順に単一HTMLアプリを作ります。WindowsではGUIまたはデスクトップのバッチランチャーから起動できます。

## v3の主な改良（2026-11-13）― 画面を全面刷新

- **手順ごとの画面遷移（ウィザード形式）**: 「準備 → ①アイデア → ②担当モデル → ③作成中 → ④完成」の順に画面が切り替わり、1画面にはその段階で必要なものだけが出ます。設定とGitHub公開は別画面に分けました。
- **老眼でも読める大きな文字**: 本文13〜15pt・見出し22〜25pt・大きなボタンに統一し、右上のボタンで「標準／大／特大」を切り替えられます。
- **起動した瞬間の期待感**: 「AIアプリ開発会社」の看板と、担当モデル名が入った4部署のカードが並ぶ最初の画面にしました。接続状態も大きく表示されます。
- **作成中が見える**: 部署カードと太い進捗バーが連動し、今どの部署が何文字まで生成したかが分かります。

## v2の主な改良（2026-11-13）

- **部署ごとにモデルを自動で切り替え（スマート自動ルーティング）**: 導入済みモデルの一覧と大きさ・系統を見て、PM・要件定義とデザイン設計には日本語と推論が得意な汎用モデル、実装とQAにはコード特化モデルを自動で割り当てます。理想のモデルが入っていなくても止まらず、今あるモデルの中で最適な組み合わせで続行し、画面に「どの部署に・どのモデルを・なぜ選んだか」を表示します。
- **途中で止まらない**: 生成をストリーミング表示にし、進み具合（生成中の文字数）が常に見えます。「中止」ボタンでいつでも止められ、完了した工程はその場で保存されるので、次回「つづきから再開」で続きだけを実行できます（最初からやり直しません）。
- **ちゃんと動くものができるまで直す**: 実装直後のチェックで問題が見つかれば、実装モデルが自動で直します（最大2回）。QAは「判定と直す点」だけを返す方式に変え（HTML全部を返させないので途中で切れません）、指摘は実装部署が直して再審査します（最大2往復）。直しきれない場合も、未検証の下書きHTMLと理由が残ります。
- **大きなHTMLが切れにくい割り当て**: 実装と修復の工程だけ、出力上限とコンテキストを自動で大きくします（既定の目安: 出力8192トークン、コンテキスト8192）。要件・設計・QAは短く速く回します。
- **画面の改良**: 部署ごとの担当モデルと進捗バーが常に見え、完成後は「生成アプリを開く」ボタンでそのままブラウザー確認できます。部署ごとのモデルは、手動モードでは導入済みモデル一覧からプルダウンで選べます（打ち間違いで止まりません）。

詳しい変更点は [CHANGELOG.md](./CHANGELOG.md) をご覧ください。

> **GitHub Pagesについて:** このリポジトリのPagesサイトは、エージェントの紹介とセットアップ案内を表示する静的ページです。Python、Tkinter、Ollamaはブラウザー上では動きません。アプリを使うには、このリポジトリをダウンロードまたはcloneし、PythonとOllamaを準備してPC上で起動してください。

## 必要なもの

- Python 3.9以降。WindowsではTkinterを含むPythonをインストールしてください。
- [Ollama](https://ollama.com/download)をインストールし、生成中は起動しておきます。
- 既定（スマート自動ルーティング）: 導入済みモデルから部署ごとに自動選択します
- 16GB RAM・Core i7級の推奨構成: `qwen3:8b`（PM・設計）と `qwen2.5-coder:7b`（実装・QA）の2本。どちらか1本だけでも動きます
- 動作が重い場合は `qwen2.5-coder:3b` や `qwen3:4b` のような小型モデルも候補になります

モデルの初回ダウンロードにはインターネット通信とディスク容量が必要です。使用する正確なモデルタグのライセンスと利用条件を、配布元で確認してください。

## ダウンロードと起動

Gitがある場合はPowerShellでcloneします。

```powershell
git clone https://github.com/jkj7vv2nd7-lang/ai-app-builder-demo.git
cd ai-app-builder-demo
```

Gitを使わない場合は、GitHubの **Code > Download ZIP** から取得し、展開したフォルダーを開いてください。

推奨モデルを取得してGUIを起動します。

```powershell
ollama pull qwen3:8b
ollama pull qwen2.5-coder:7b
python .\app_gui.py
```

Windowsでは`launch_gui.bat`をダブルクリックしても起動できます。デスクトップに置く場合は、バッチファイルを右クリックして「ショートカットの作成」を選び、作成したショートカットをデスクトップへ移動します。

コマンドラインから直接実行することもできます。

```powershell
python .\app_builder.py "中学生向け英単語クイズアプリ"
```

### モデルの使い方（3つのモード）

- **スマート自動ルーティング（既定・おすすめ）**: GUIで「自動で部署ごとに切替」、CLIでは既定のまま（`--routing-mode smart`）。導入済みモデルを調べ、部署ごとに最適なものを選びます。モデルは1本だけでも動きます。理想のモデルが無い場合は、導入すると良くなるモデル名をログに案内するだけで、処理は止めません。
- **単一モデル**: GUIで「単一モデル」、CLIでは `--routing-mode single`。全工程を同じモデルで実行します。
- **部署ごとに手動**: GUIで「部署ごとに手動で選ぶ」、CLIでは `--routing-mode manual` と `--planning-model` / `--design-model` / `--implementation-model` / `--qa-model`。PM・設計・実装・QAの4部署を別々に指定できます。

```powershell
python .\app_builder.py "家計簿アプリ"
python .\app_builder.py "家計簿アプリ" --routing-mode manual --planning-model qwen3:8b --design-model qwen3:8b --implementation-model qwen2.5-coder:7b --qa-model qwen2.5-coder:7b
```

モデルはAPI呼び出し後にアンロードされるため、部署の切り替え時にロード待ちがあります（16GBメモリを守るための仕様です）。コンテキスト長の目安は4096で、実装工程だけ自動で最大8192まで広げます。メモリ不足や遅さがある場合はGUIで2048に下げ、小さなモデルを検討してください。

### 中止と再開

生成中は「中止」ボタンで止められます。完了した工程（要件・設計・検証済みHTML）は実行フォルダーに保存済みなので、GUIの「つづきから再開」でそのフォルダーを選ぶか、CLIで指定すれば、続きの工程だけを実行します。

```powershell
python .\app_builder.py --resume .\runs\run_20261113_120000_abcdef
```

## 入力例と成果物

最初の入力は、普段の言葉で書いた一文のアイデアで十分です。対象者や画面構成、技術用語を最初から決める必要はありません。分野別の短い例は[入力プロンプト例](./prompt_examples.md)を参照してください。

生成されたアプリは`runs\run_<日時>_<識別子>\`に保存されます。要件、設計、AIの実装・QA応答、静的チェック結果、ログ、状態ファイルを同じ実行フォルダーで確認できます。既存の実行結果やパッケージ直下のファイルは上書きしません。

## このパッケージのGitHub Pagesサイト

このリポジトリには、エージェントの紹介・セットアップ用の`index.html`が含まれます。自分の公開URLで同じ案内ページを表示するには、GitHubでこのリポジトリを開き、**Settings > Pages > Build and deployment**へ進みます。

1. Sourceで **Deploy from a branch** を選択
2. Branchで **main**、フォルダーで **/(root)** を選択
3. **Save**を押し、GitHubのデプロイ完了を待つ

公開後のURLは通常`https://<owner>.github.io/<repository>/`です。このページは説明用の静的サイトで、AIアプリ開発エージェントをWeb上で実行するものではありません。

## 生成したアプリを公開する場合

GUIには生成HTMLをGitHubへアップロードする機能があります。公開リポジトリはソースも誰でも閲覧できるため、内容を確認してから操作してください。アプリはリポジトリを作成せず、ユーザー作成済みの公開リポジトリURLを要求します。既定ブランチに`index.html`が既にある場合は上書きせず停止します。そのため、生成HTMLの公開先にはこの配布用リポジトリではなく、別の空の公開リポジトリを使ってください。

GitHub CLIとGitを導入し、PowerShellで認証します。

```powershell
gh auth login
gh auth setup-git
```

Git認証がすでに設定済みなら`gh auth setup-git`は不要です。GUIの確認画面で対象リポジトリと`index.html`だけが公開されることを確認してアップロードします。既存内容の上書き、強制push、Pagesの有効化は行いません。アップロード後は対象リポジトリの **Settings > Pages** で **Deploy from a branch**、既定ブランチ、`/(root)`を選んで保存してください。アプリはトークンを保存しません。

## 制約と安全上の注意

- 生成物は単一HTMLを前提とします。静的チェックとAI QAだけでは、実ブラウザーでの動作を保証しません。Playwrightによるローカル検証は任意です。
- 外部通信検出はヒューリスティックで、すべてのネットワークアクセスを検知できる保証はありません。Ollama生成リクエストはローカルの`localhost`へ送信します。
- GitHub Pagesや公開リポジトリを使うと、サイトとソースがインターネットから閲覧可能になります。個人情報、認証情報、秘密情報を含む内容を公開しないでください。

## テスト

追加パッケージなしで、パッケージのルートから実行できます。

```powershell
python -m unittest discover -s .\tests -v
```

公開機能のテストはGit/GitHub CLIをモックします。実際のGitHubへのアップロードやGitHub Pagesのデプロイを検証するものではありません。
